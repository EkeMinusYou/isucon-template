# ベンチマーカーの振る舞い

ベンチマーカーがどう動き、何を判定するかについて、観測から分かったことを残す。
ユーザーなどの利用者が何を見てどのAPIをどの順・条件で呼ぶか、警告・失敗が出る条件、
負荷の増減の条件などが対象。こちらの実装の状態（CPU、待ち、処理量）は書かない。

ベンチマーカーのソースは読まない。参加者向けベンチ出力、アクセスログ、ユーザー遷移、
アプリ側の記録など、許可された観測から導く。

## 書き方

- 1項目は見出し1つと、日時付きの箇条書き。最初の行に確度（確定・有力・仮説）と根拠を書く。
- 根拠には、比較したRUNと値、再実行できるクエリやファイルの場所を書く。
- 設計への影響（避けるべき変更、効く変更）を書く。
- 追記と訂正だけで更新し、全体を書き直さない。確度の変更や反証は、その項目に日時付きの行を足す。

```markdown
### <ベンチマーカーの振る舞いを1文で>
- YYYY-MM-DD HH:MM 仮説：<内容>。根拠：<RUN・値・クエリ>。影響：<設計への影響>
- YYYY-MM-DD HH:MM 確定に変更：<追加の根拠>
```
