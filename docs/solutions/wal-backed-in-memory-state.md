# GoのWAL付きオンメモリ状態

通常処理の正本をメモリに置き、受理済み更新を追記ログから復元する方法です。ファイル読み書き、snapshot、replayをGoで実装します。

## 状態と受理の境界

操作ID、対象キー、順序、更新内容を記録し、応答・メモリへの公開・ログへの記録の順序を決めます。同じキーへの更新、重複要求、外部サービスの副作用、失敗時の結果を公式仕様と一致させます。外部副作用をreplayで無条件に再実行しません。

通常のサービス・OS再起動で受理済み更新を失わないよう、書込み・flush・終了処理・再生を設計します。電源断への耐性は追加要件にしません。破損・不完全な末尾、version不一致、重複、世代違いを検出し、勝手に成功扱いで読み飛ばしません。

## 初期化・復元

初期データは独立ファイルから読み、必要な索引を構築します。初期化中の新規要求を制御し、全関連状態と永続化世代を揃えてから公開します。永続ファイルはdeployが削除するディレクトリの外へ置きます。

ログ量と復元時間が問題になる場合はsnapshotとログの世代交代を設計し、対応する位置から一度だけreplayします。受理済み更新の復元に必要な部分を集計用の都合で削除しません。

計測・保存は[WALの分析と保存](../measurement/wal-analysis.md)に従います。WAL全体を毎回回収せず、標準集計と必要な対象範囲を利用します。
