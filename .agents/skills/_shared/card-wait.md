# カード処理の継続・待機・終了

isucon-workerとisucon-investigateは、開始時・各カードの処理後にこの手順に従う。カード単位の完了とスキル全体の終了を区別する。

## 継続の判断

Backlog CLIで最新のカード一覧を取得し、担当範囲・Priority・Owner・依存と各Skillの実行制約を再確認する。Owner・依存・他作業との競合の条件を満たす対象があれば、各Skillの通常手順で取得・処理し、処理後に再びこの判断へ戻る。一件の処理完了や残件数の報告だけで終了しない。読み取り失敗を対象0件として扱わない。

ユーザーによる対象・件数の制限、停止指示、待機不要の指示を優先する。指定件数の処理完了や停止指示があれば終了する。処理可能な対象がなければ、以下の待機へ進む。処理済みカードが0件でも待機を省略しない。

## カード追加待機

1. 対象がないことと、カードの追加・状態変更を待つことを報告する。
2. ユーザーが待機時間を指定していなければ、60秒間隔で最大5分間待つ。各待機後にBacklog CLIで最新のカード一覧を取得し、担当範囲・Priority・Owner・依存を再確認する。読み取り失敗を対象0件として扱わない。
3. 処理可能な対象が見つかったら待機を切り上げ、継続の判断へ戻る。処理後に再び対象がなくなったら、その時点から待機時間を数え直す。
4. 待機期限に達した時点でも再確認し、対象がなければその旨と待機結果を報告して終了する。ユーザーが停止を指示した場合は待機を打ち切る。待機不要・単発処理などの明示指示があれば、それを優先する。

待機中に担当外のカードを取得したり、待機を埋めるためにカードを新規作成したりしない。

終了時は各Skillの検証・報告要件に従い、終了理由も報告する。
