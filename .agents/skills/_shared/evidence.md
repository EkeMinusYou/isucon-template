# Evidence

`AGENTS.md`の共通ルールに加え、改善案の選択・採否に必要な範囲で使う。

## 根拠と比較

- 公式仕様、現行コード・設定、保存済みRUNを根拠とし、観測事実・推論・未確認点を分ける。
- 比較基準は検証したい変更前の構成とRUNにする。コード・配置・計測条件の差を確認し、意図した変更と、それ以外の条件差を区別する。退行を修正した場合も、元の変更前と比較する。

## 仮説と結果の評価

- まずシナリオを解析し、得点の伸びを妨げていると考えられる要因を探る。公式仕様、アプリの実装、許可された観測をもとに、得点につながる操作の実行条件や順序、操作間の依存関係、待機や失敗の影響、負荷が増減する条件を整理する。
- 改善仮説では、変更が得点対象操作の回数・成功率・1回あたりの得点・失敗や未完了による損失にどう作用するかを予測する。CPU時間や待ち時間の削減を根拠にする場合は、その負担が得点対象操作を制約していると考える根拠も示す。変更で増える処理や待ち、正当性への影響も確認する。
- 複数の改善候補がある場合は、根拠に基づいて予測する得点改善幅が最も大きい案を優先する。根拠の強さは、得点予測の確からしさとして評価する。数値化できない場合も、候補間の大小を判断する根拠と未確認点を示す。候補の優劣を判断するために未確認点の切り分けが必要なら、分析・計測・実験を先行させる。
- 予測を確かめる指標として、操作の実行回数、成功件数、待ち時間などから適切なものを選ぶ。まず既存成果物で確認し、追加計測は必要な範囲に絞る。得点改善幅が未確定でも、得点への作用を説明でき、仮説を確かめる評価方法があれば実装・計測に進める。
- 結果は基準RUNと比較し、変更が狙った処理・待ち・資源消費に作用したか、得点対象操作の進行が変わったか、得点が変わったかを分けて評価する。実験前の予測と照合し、得点への作用について支持された仮説・支持されなかった仮説・未確定の仮説を区別する。局所指標の改善やスコアの横ばいだけで、得点への効果を判断しない。観測不足やRUN間の変動で判別できない結果は未確定とし、優先順位を上げ下げする根拠にしない。
- 変更の採否と、次にどの仮説を検証するかを分けて判断する。採用した変更への追加最適化を既定にせず、結果を、同じ得点制約や因果関係を前提とする他の改善候補にも反映し、次に選ぶ候補と理由を示す。

## 想定外の結果と停滞

予測と異なる結果は、基準RUNと今回のRUNの対応する負荷区間で、ユーザー遷移、API別件数、結果の内訳、進捗ログ、警告を比べて切り分ける。変更で増えた処理や待ち、警告・失敗の増加も確認する。

| 観測した結果 | 次に優先する作業 |
| --- | --- |
| 狙った処理・待ち・資源消費が変わらない | 実装、適用条件、計測を確認し、変更が仮説を検証できていたかを調べる |
| 狙った処理は改善したが、得点対象操作の進行が改善しない | 予測した制約を十分に軽減できていたかを確認する。軽減できていたなら、その制約が得点を妨げているという仮説と、それに依存する他の候補の優先度を下げる。操作の開始条件、待機、失敗・再試行などから別の制約を調べる |
| 得点対象操作の進行は改善したが、得点が伸びない | 1回あたりの得点、減点、他の得点機会の減少、集計範囲を調べる |
| 観測不足やRUN間の変動で判別できない | 効果を未確定とし、候補を見分けるために必要な既存成果物の分析、追加計測、小さな実験を選ぶ |

- 予測と食い違った因果仮説による追加改善へ進むには、食い違いの説明と、次案を支持する新しいEvidenceまたは成立条件の変化を必要とする。変更する技術や関数が違っても、前提とする得点制約が同じなら同じ因果仮説として扱う。
- 複数の変更で同じ失敗や停滞が続く場合は、共通する実装上の前提・比較条件・観測方法を再評価し、改善対象や構成の置き換えも比較する。

## 計測負荷の切り分け

- pprofなどの採取処理や計測用ログのCPU・I/O・待ちが目立つ場合は、その負担を減らすアプリ改修に進む前に、同じアプリ・配置で負担の疑われる計測の有無を比較する。スコア・処理量・遅延への影響を分離し、計測条件も見直す。採取が重い条件で得た律速判断は、その条件とともに扱う。
- 比較実験での一時停止と、以後の改善・得点計測で計測を外す判断は分ける。改善候補が見つからないことだけを理由に、計測を外さない。
- 継続的に計測を外すのは、比較実験で計測負荷が得点を制約していると確認でき、計測を維持する実装・配置の改善や、採取頻度・対象・記録量の削減では必要な改善を得られないとEvidenceに基づいて判断した場合に限る。
- 計測を外す場合も、公式の合否、RUNの構成・計測条件・成果物状態を残す。失われる観測と以後の判断への影響を明示し、計測条件以外を揃えた比較で得点改善と正当性を確認する。RUN間の変動と区別できなければ再比較し、改善を確認できなければ計測を戻す。

## 調査の範囲

- 調査では、その結果でどの判断が変わるかを明確にし、判断を変えない精密化や再調査を続けない。
