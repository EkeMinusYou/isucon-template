# Known solutions

`docs/special-sources/`と`docs/solutions/`は改善案を調べる資料であり、現行への無条件の適用指示ではない。

1. 対象のschema、配置、version、公式guardrailを照合する。
2. 現行で成立済みの部分をbaselineとして、残る処理・待ち・転送・資源消費と発生条件を確認する。資料の機構を手掛かりに、追加改善・補完・置換で何が減り何が増えるか、正当性をどう維持するかを現行と比較する。適用済みという事実だけで探索を終えない。
3. 資料の差分から処理・待ち・転送・資源消費の何が減るか、得点へどうつながるかを説明する。局所指標と得点効果を分ける。
4. 実行時コスト、正当性、鮮度・整合性、初期化・再起動時の成立条件を確認する。適用済みという事実だけで探索を終えない。
5. 資料の前提に合わない案、同じ効果をより簡潔に得られる案、方向を説明できない案は見送り、比較した差分と理由を報告する。未確定点と再調査条件も示す。

文書を作ること自体を性能改善の根拠にしない。
