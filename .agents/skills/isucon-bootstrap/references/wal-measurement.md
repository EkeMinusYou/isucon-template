# WAL構成の計測

メモリ＋WALへの移行時に読む。[標準計測の確認手順](../../isucon-setup/references/measurement.md)を使い、生成・回収・集計を移行後の構成へ合わせる。ここでは競技固有のAPIや固定の段階を定義しない。

## 得点操作の進行を追う

- 公式の得点条件と現行コードから、観測単位と主要な段階を定義する。利用者、注文、予約などの単位を区別し、開始・得点操作・完了・次の開始を実際の状態遷移に対応付ける。開始できた対象だけでなく、開始前を観測できる情報源も確認する。
- 既存アクセスログとWALのどちらで各段階を判定できるかを整理する。WALに失敗・読み取り・未開始の履歴がないこともあるため、WALだけで全進行を説明できるとみなさない。必要な境界が観測できなければ、目的を絞った指標やログを補う。
- 時刻、利用者・処理対象の識別、世代・sequence、成功・失敗の意味を対応付ける。Cookieのない登録要求と認証後の要求を無根拠に結び付けず、HTTP成功と業務上の完了、受理とWAL追記完了を区別する。
- 段階ごとの到達件数と、段階間の経過時間・再試行・最後の観測結果を必要な範囲で集計する。得点の件数・価値・減点は得られる内訳を使い、観測できない損失や次へ進まない原因を推測で数値化・断定しない。

## 同じRUNへ回収し、分析につなぐ

- 既存のcollector/digester・`after-bench`へ回収を接続し、必要な履歴を対象RUNへ保存する。初期化・rotation・次RUNで失われる前に回収し、RUN、ホスト、世代、開始・終了sequenceと時刻、回収状態を識別できるようにする。
- 非同期WALは、負荷終了時点で未追記の受理済み更新をどう扱うかも定める。稼働中ファイルの不完全なコピーを全履歴とみなさず、整合した読み取り範囲を確定する。回収のために負荷中の同期や全状態走査を増やさず、計測負荷を確認する。
- 競技・解法依存のparserやSQLは`tools/contest/`、宣言が必要なタスクは`Taskfile.contest.yml`へ置く。既存DuckDBの`tools/analysis/sources.yaml`へ接続し、`task q`でRUN比較に使えるqueryを用意する。未実装の共通レポート機能を前提にしない。
- 実RUNで元ログ・WALと集計を照合し、重複、再試行、世代違い、識別欠損、負荷終了時点の途中処理を確認する。観測不能・回収不足・負荷終了による打ち切りを、失敗や未開始へ誤算入しない。比較RUNの母数・時間窓・計測条件も示す。

復元用WALの仕様や保存期間を分析の都合だけで変えない。過去RUNへ現在のWALを代用せず、必要な履歴を取得していないRUNは観測範囲を限定する。
