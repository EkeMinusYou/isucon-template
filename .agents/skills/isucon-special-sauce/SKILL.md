# ISUCON 秘伝のタレを現行設定へ適用

指定資料の設定を現行環境・公式仕様と照合し、正当性と改善機構を確認できた変更を実装して正規deployする。ベンチはユーザーが実行する。

## 対象を選ぶ

- 指定があれば、`docs/special-sources/` 内のパス、ファイル名、カタログのリンク、一意な名称から対象を解決する。文書指定は文書全体、節・設定項目の指定はその範囲、複数指定は和集合だけを調べる。
- 指定がなければ `docs/special-sources/README.md` と実際のファイル一覧を照合し、ルート README 以外の全 Markdown 文書を調べる。カタログ未掲載の文書も含め、差分を報告する。
- 指定が曖昧または対象が存在しない場合は、対象を確認する。全件調査へ勝手に広げず、対象確定までは変更しない。

## 現行設定と照合して実装・deployする

指定資料を現行設定・コード・公式仕様と照合する。出典、現行値、採用する値、その差分、設定の生成元と反映先、改善機構、正当性への影響を整理する。効果量が未計測でも、設定が減らす仕事・待ちと得点へつながる経路を説明できれば適用候補にできる。公式要件と矛盾する値、根拠のない値、現行環境で反映先を確認できない変更は適用しない。

[既知資料の候補評価手順](../_shared/known-solutions.md)に従い、適用済みの設定も現行の負荷・配置に対して追加改善できるか比較する。重複する変更や適用できない変更は差分と理由を記録する。部分適用なら未反映部分も評価し、一体で反映すべき設定群はまとめて変更する。

適用済み設定との差分を調べ、追加で改善できる変更だけを選ぶ。一体で反映すべき設定群はまとめて変更し、設定の生成元を編集する。生成物を直接編集せず、Taskfileと正規のdeploy経路を使う。deploy前に対象ホストとserviceへの影響を確認し、進行中RUNとdeploy/restartを重ねない。必要なローカル設定検査・buildを行い、deploy後は対象serviceと実効設定を確認する。

## 完了報告

指定対象／全件の別と調査文書、採用した差分、実装・deploy結果、出典リンク、見送った変更と理由、未確定点を簡潔に報告する。ベンチを実行せず、計測で確認すべき効果を明記する。
